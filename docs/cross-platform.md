# Windows / macOS 兼容与悬停查询

## 当前行为

两种系统共用识别、中文资料、卡图来源、翻译缓存和 Qt 浮卡。默认按住 `Ctrl+Alt`（Mac 显示为 `Ctrl+Option`），将指针移到卡牌上停稳 0.6 秒后查询；松开组合键任意一键立即收起。悬停时间可设为 0.3–2 秒。轻微抖动不重置计时，已确认卡框内移动不反复识别；移动到其他卡牌后重新计时。

切换应用、最小化或换了游戏窗口会终止本次悬停，返回游戏后需松开并重新按键。指针移入浮卡时保留结果并暂停新查询，触控板/滚轮可以阅读长文本。关闭按钮或 Esc 也可终止查看。悬停模式不拦截游戏的鼠标点击；Windows 原有的组合点击和查询点击拦截保留为设置中的可选方式，Mac 也有对应实现。

浮卡和网页阅读区按卡名、特性/招式名、效果逐项展示中文和英文，HP、伤害等数值只显示一次。缺失中文时自动翻译当前查询卡牌的对应英文；已有中文（包括本地参考译文）优先使用。英文先显示，翻译随后补入；失败时英文仍可阅读，没有翻译按钮。`译` 标记参考译文或机器翻译。匹配到的简中卡图效果可补充中文，但不会覆盖英文原文。

松开或关闭会推进查询编号，并清空待处理识别、卡图、翻译任务。已执行中的网络请求可能继续完成并保存缓存，但结果不能重新弹窗，也不能更新下一张卡。

## 系统边界

- `platform_backend/contracts.py` 定义公共能力与帧坐标快照。历史字段 `hwnd` 表示不透明窗口 ID，不要求上层理解其原生含义。
- `platform_backend/windows/` 保留 Windows Graphics Capture、Win32 窗口状态、鼠标钩子和 DPI 映射。
- `platform_backend/macos.py` 使用 PyObjC 调用 ScreenCaptureKit、Quartz、Cocoa。当前使用 macOS 14+ 的 SCScreenshotManager 限速采集单个窗口，最多约 10 帧/秒，只保留最新帧。截图通过 CGImage 转换成 BGR，不假定原生像素格式。
- `overlay_input.py` 共用悬停状态机；平台仅提供按键状态、指针位置、前台/遮挡判定。组合点击由原生输入后端处理。
- `live_capture.py`、`window_capture.py`、`overlay_geometry.py` 保留原来的入口名称并转发到后端。离线识别与网页服务不会加载 Windows 原生库。

Windows 桌面坐标使用物理像素，Mac 使用屏幕点；帧始终是图像像素。通过内容区域和实际帧尺寸映射指针。Mac 帧附带采集时窗口/内容区域快照，窗口等比例缩放也会拒绝旧帧。Qt 浮卡坐标在后端转换，不能简单给全部坐标乘 Retina 倍率。

## Mac 启动准备

需要 macOS 14 或更新版本。`uv sync` 按系统安装 Windows 或 PyObjC 依赖，不需要手工改依赖文件。

```sh
uv sync
uv run ptcglens.py --overlay --check-permissions
```

浮卡查询需要屏幕录制、辅助功能和输入监控权限，网页采集只检查屏幕录制权限。首次实际启动会调用系统授权提示；开发环境中需授权实际承载 Python 的终端或应用，授权后重新启动。检查命令只检查，不弹授权请求，也不需要卡牌索引。

例如从 ChatGPT 内启动时，系统可能将权限归属到 ChatGPT；仅开启桌面自动化工具的权限不会让 Python 后端获得权限。授权后应重启对应宿主应用，再重新运行检查命令。

默认优先检查真实 Mac 游戏验证过的目录：卡图在 `~/Library/Caches/com.pokemon.pokemontcgl`，英文数据库在 `~/Library/Application Support/com.pokemon.pokemontcgl/config-cache`；也保留旧 Unity 路径作为候选。不会扫描整个用户目录。默认路径不匹配时使用：

```sh
uv run python cache_watch.py --once --cache-root "/实际卡图目录" --game-cache "/实际数据库目录"
uv run ptcglens.py --overlay --cache-root "/实际卡图目录" --game-cache "/实际数据库目录"
```

两边均需英文缓存和单独下载的中文对照表。Mac 的 `--capture-mode screen` 仍按目标窗口采集，防止浮卡进入画面；Windows 的该选项保留前台截屏兼容方式。

## 验证与边界

自动测试覆盖原有识别、索引、卡图、Windows 采集裁剪与输入逻辑，以及新增悬停计时、抖动、卡牌切换、松开取消、失焦后重新按键、迟到结果隔离、自动翻译、英文保留、双语滚动布局和 Retina 帧映射。Windows 原生适配器可在 Mac 上使用系统调用替身运行，替身测试不等于 Windows 游戏现场验收。Mac 原生绑定、配置选择器和 CGImage/BGR 转换可独立验证，不采集其他应用。

`.github/workflows/tests.yml` 配置 Windows/macOS、Python 3.12/3.13 的测试矩阵。只有实际运行后的 CI 结果才算通过，提交代码不会自动产生已通过的结果。

Windows 仍需真实游戏现场验收；Mac 的现场结果记录在下方。两边的无边框/全屏、多显示器不同缩放和长时间运行资源占用仍待检查。

### Mac 真实游戏验证（2026-10-17）

在 Apple Silicon Mac 的实际游戏中完成以下检查，原始截图、日志与报告保存在本地 `output/mac-validation/`（不提交游戏截图）：

- 发现实际缓存路径并修正默认值；首次建立 73 张卡的本地索引，随后实时更新至 81 张。英文资料和中文对照表正常加载。
- ScreenCaptureKit 可采集 Retina 游戏窗口；授予辅助功能并重启后，内容区域正确排除标准标题栏，从 1280×748 点窗口得到 1280×720 点游戏区域。
- 游戏处于后台时连续取得 26 帧；窗口切换到其他桌面不可见时停止采集并等待恢复。
- 对实际对局截图验证己方战斗区/备战区、对方战斗区/弃牌区、手牌的支援者/物品/能量以及背景。8 个点分别按 4 个比例回放，32/32 正确，未误识别背景。该结果验证图像缩放，不代表已验收实际窗口缩放和全屏。
- 对缺少中文效果的 Chikorita 自动发起翻译，结果回填双语浮卡，英文原文保留；已检查实际渲染截图。
- 授权并重启后，屏幕录制、辅助功能、输入监控检查全部通过，原生浮卡程序成功启动。

现场回放用例为 `tests/scenes/mac-live-cases.json`，需本地截图后运行：

```sh
uv run python query_regression.py --cases tests/scenes/mac-live-cases.json --sample-root output --output output/mac-validation/regression.json
```

真实游戏验证定位并修复了两类浮卡问题：

- Vibe Island 的透明悬浮窗口会被系统列为 `alpha=1` 的大矩形。Mac 后端在出现覆盖矩形时使用辅助功能实际命中所属应用判定，保留真实遮挡，并补充透明浮层、真实遮挡和命中失败的回归检查。
- Mac 工具窗口默认会在应用失焦时隐藏。浮卡开启失焦仍显示，并通过原生后端设置跨桌面与全屏辅助窗口，保持非激活行为。该设置不等于已完成游戏全屏验收。

修复后已连续记录伊布悬停查询、双语内容和松开关闭；原生 `NSWindow` 确认在游戏当前桌面实际可见，用户也确认“看到了，松开关闭”。不能单独把 Qt 的 `isVisible()` 当作现场显示验收。`--diagnose-input` 支持输出悬停坐标、游戏前台、区域与遮挡状态。

Python 3.12.9 和 3.13.5 均通过 136 项测试。Windows 游戏实机、Mac 游戏全屏、多显示器和长时间运行仍按上方边界保留待验收。

### 本次本地验证（2026-10-14）

在 Apple Silicon Mac 上，Python 3.12.9 和 3.13.5 均通过 133 项公共/适配器测试，网页自动双语 Node 测试通过；原生 Cocoa 双语浮卡已成功显示并自动关闭。依赖锁文件保留既有包版本，仅增加 Mac 条件依赖。当前运行环境没有游戏缓存和采集/输入授权，权限诊断正确报告缺项；不把原生 API 导入成功或替身测试记成真实游戏通过。
