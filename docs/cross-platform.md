# Windows / macOS 兼容与悬停查询

## 当前行为

两种系统共用识别、中文资料、卡图来源、翻译缓存和 Qt 浮卡。默认按一下 `Ctrl+Alt`（Mac 显示为 `Ctrl+Option`）开启查询模式，松手后将指针移到卡牌上停稳 0.6 秒查询；再按一下关闭。开启时图标变色，菜单显示开关状态。悬停时间可设为 0.3–2 秒。轻微抖动不重置计时，已确认卡框内移动不反复识别；移动到其他卡牌后重新计时。原长按和组合点击模式保留，已保存的旧模式不会被强制覆盖。

切换应用、最小化或换了游戏窗口会关闭查询模式，返回游戏后需重新按键开启。指针移入浮卡时保留结果并暂停新查询，松手后触控板/滚轮可以阅读长文本。关闭按钮或 Esc 也会关闭查询模式。悬停模式不拦截游戏的鼠标点击；Windows 原有的组合点击和查询点击拦截保留为设置中的可选方式，Mac 也有对应实现。

浮卡和网页阅读区按卡名、特性/招式名、效果逐项展示中文和英文，HP、伤害等数值只显示一次。缺失中文时自动翻译当前查询卡牌的对应英文；已有中文（包括本地参考译文）优先使用。英文先显示，翻译随后补入；失败时英文仍可阅读，没有翻译按钮。`译` 标记参考译文或机器翻译。匹配到的简中卡图效果可补充中文，但不会覆盖英文原文。

关闭查询模式（长按模式则为松开按键）会推进查询编号，并清空待处理识别、卡图、翻译任务。已执行中的网络请求可能继续完成，但后续翻译重试会取消，结果不能重新弹窗，也不能更新下一张卡。

新卡默认每 5 秒增量检查，未确认查询可唤醒立即检查；连续检查至少间隔 1 秒。游戏尚在写入的卡图会继续等待，索引更新后，仅对查询模式仍开启且未失焦的未确认悬停重新计时。首次画面未就绪或窗口切换导致的采集错误最多自动重试两次，关闭模式可取消。翻译对临时网络错误、服务繁忙和限流每段最多尝试三次，不重试明确的请求错误；英文不受影响。

## 系统边界

- `platform_backend/contracts.py` 定义公共能力与帧坐标快照。历史字段 `hwnd` 表示不透明窗口 ID，不要求上层理解其原生含义。
- `platform_backend/windows/` 保留 Windows Graphics Capture、Win32 窗口状态、鼠标钩子和 DPI 映射。
- `platform_backend/macos.py` 使用 PyObjC 调用 ScreenCaptureKit、Quartz、Cocoa。当前使用 macOS 14+ 的 SCScreenshotManager 限速采集单个窗口，最多约 10 帧/秒，只保留最新帧。截图通过 CGImage 转换成 BGR，不假定原生像素格式。
- `overlay_input.py` 共用悬停状态机；平台仅提供按键状态、指针位置、前台/遮挡判定。组合点击由原生输入后端处理。
- `live_capture.py`、`window_capture.py`、`overlay_geometry.py` 保留原来的入口名称并转发到后端。离线识别与网页服务不会加载 Windows 原生库。

Windows 桌面坐标使用物理像素，Mac 使用屏幕点；帧始终是图像像素。通过内容区域和实际帧尺寸映射指针。Mac 帧附带采集时窗口/内容区域快照，窗口等比例缩放也会拒绝旧帧。Qt 浮卡坐标在后端转换，不能简单给全部坐标乘 Retina 倍率。

## Mac 启动准备

需要 macOS 14 或更新版本。`uv sync` 按系统安装 Windows 或 PyObjC 依赖，不需要手工改依赖文件。

```sh
uv sync
uv run ptcglens.py --overlay --check-permissions
```

浮卡查询需要屏幕录制、辅助功能和输入监控权限，网页采集只检查屏幕录制权限。首次实际启动会调用系统授权提示；开发环境中需授权实际承载 Python 的终端或应用，授权后重新启动。检查命令只检查，不弹授权请求，也不需要卡牌索引。

浮卡模式首次启动可自动从已有游戏缓存建立索引。缓存尚未下载时保持等待，可从托盘的“运行状态与准备”查看准备进度、采集状态及目录。没有上游中文目录时，仍可使用本地补充和自动翻译。权限缺项以窗口提示说明，不要求用户从终端日志判断；网页模式仍可使用手动建索引命令。

例如从 ChatGPT 内启动时，系统可能将权限归属到 ChatGPT；仅开启桌面自动化工具的权限不会让 Python 后端获得权限。授权后应重启对应宿主应用，再重新运行检查命令。

默认优先检查真实 Mac 游戏验证过的目录：卡图在 `~/Library/Caches/com.pokemon.pokemontcgl`，英文数据库在 `~/Library/Application Support/com.pokemon.pokemontcgl/config-cache`；也保留旧 Unity 路径作为候选。不会扫描整个用户目录。默认路径不匹配时使用：

```sh
uv run python cache_watch.py --once --cache-root "/实际卡图目录" --game-cache "/实际数据库目录"
uv run ptcglens.py --overlay --cache-root "/实际卡图目录" --game-cache "/实际数据库目录"
```

两边均需英文缓存，单独下载的中文对照表为可选项。Mac 的 `--capture-mode screen` 仍按目标窗口采集，防止浮卡进入画面；Windows 的该选项保留前台截屏兼容方式。

- Vibe Island 的透明悬浮窗口会被系统列为 `alpha=1` 的大矩形。Mac 后端在出现覆盖矩形时使用辅助功能实际命中所属应用判定，保留真实遮挡，并补充透明浮层、真实遮挡和命中失败的回归检查。

### 慢查询响应处理（2026-10-17）

窗口检测移入后台，界面与输入回调不再同步等待 Mac 辅助功能读取；窗口快照超过 1 秒失效，不继续使用旧坐标。识别增加约 5 秒预算、阶段与候选循环取消检查，界面单独显示计时并在超时后推进查询编号，丢弃迟到结果。修复可见浮卡替换提示时新标签延后显示、被算成零高度的问题。

浮卡启动前将 OpenCV 内部并行限制为最多 2 个线程；本机 GCD 后端忽略正数设置，实际改为关闭内部并行，报告 1 个线程。识别仍在后台线程运行。相同 52 点回放全部通过，串行模式 P50/P95 为 313.6/673.3 ms，原 8 线程为 176.2/424.1 ms；这是降低并行资源竞争的取舍，不是加速承诺。

Python 3.12、3.13 均通过 163 项测试。模拟 5.6 秒慢任务时，Qt 20 ms 计时器最大间隔 24.7 ms，5.008 秒发出超时取消，迟到结果被忽略；后台窗口检查被阻塞时，读取快照仍立即返回。单个正在执行的原生识别调用不能被 Python 检查点强行终止，会在返回后检查取消。以上为自动测试与模拟，用户报告的现场假死仍需回归确认。

### 单次开关悬停查询（2026-10-17）

用户确认慢查询时游戏仍可操作，主要问题是浮卡一直停在识别中；等待体验由上节的计时、超时和可见提示处理。交互默认改为单次快捷键开关：开启后松手悬停换牌，再按一下关闭，原长按和组合点击模式仍可选择。既有设置的模式偏好保留，本次按用户选择将本机设置切到 `toggle`。

开关只在按下沿切换，长按不反复切换；松开后识别、翻译、卡图与新卡缓存重试保持当前查询会话。再次按键、Esc、关闭浮卡、切走游戏或窗口失效会取消会话，迟到结果不能重新弹出。菜单栏/托盘通过图标颜色和菜单状态反馈是否开启；关闭状态不会覆盖索引准备进度。

Python 3.12、3.13 均通过 171 项测试，新增松手换牌、第二次按键关闭、持续按键不重复切换、失焦防误开启、浮卡阅读和取消后结果隔离。已检查设置界面与模式保存、开关状态提示。

Mac 单次开关模式现场验收通过：用户确认“窗口和全屏都正常，操作更方便”。日志记录在全屏 `(0,33)-(1470,956)` 和窗口内容区域 `(36,112)-(1316,832)` 中，实体快捷键已松开时查询仍开启、浮卡实际可见；全屏连续识别到 `me5_en_002`、`me5_en_003`。本地诊断保存在 `output/toggle-validation/`，不提交游戏截图。此验收涵盖新交互的开关、换牌与显示，Windows 实机、多显示器及长时使用仍待验证。

### Retina 慢查询修复（2026-10-24）

用户连续遇到 5 秒识别超时。用报告中的牌桌截图回放，放大至 3192×1428 时，己方战斗区一次正确识别耗时 7.63 秒；特征计算与匹配是主要开销。局部裁剪以前随整个窗口放大，即使已裁掉无关区域仍可能包含数百万像素。
