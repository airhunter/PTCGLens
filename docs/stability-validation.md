# 查询稳定性验证

2026-10-04。按用户确认的顺序，继续中文覆盖与稳定性，发布和打包最后处理。

## 修正内容

- 查询和卡图任务队列各只保留一项待处理请求。正在执行的旧查询完成后仍按编号丢弃；新点击不会积压大量截图。不同字段的按需翻译仍保留各自任务。
- 仅中文资料变化时复用已有 SIFT / FLANN 索引；卡图新增或变化时才重建视觉资源。网格识别不再保留旧的完整资源元组，完成查询后释放资料快照。
- 合并 SIFT 描述子时避免重复复制已有浮点数组。当前索引有 762422 个描述子，基础内存占用仍较高。
- Windows 原子替换期间的短暂文件共享冲突，读取端也做有限重试。无效 JSON 仍明确失败，更新失败保留旧资料。
- 未识别的查询自动留存最近 10 组画面与元数据到 `output/query-failures/`。每组记录点击点、客户区、结果及图片 SHA-256；仅保存在本机。`--diagnose-input` 可记录成功查询，仍使用同一数量上限。诊断写入失败仅记日志，不覆盖已经显示的识别结果。

## 复测入口

```powershell
uv run python -m unittest discover -s tests
uv run python query_regression.py --output output/query-regression-stability.json
uv run python stability_check.py --duration 120 --burst-size 30 --live-capture
```

两个截图脚本需要本地卡图索引、`output/card-data.json` 和 `tests/scenes/query-cases.json` 对应的全部截图。图片不随源码提交。压力测试默认只回放本地截图；加 `--live-capture` 后需游戏已打开，可同时只读观察后台采集。它不发送鼠标输入、不联网获取卡图，也不修改正在运行程序的缓存。

报告分别写入 `output/query-regression-stability.json` 和 `output/stability-check.json`，均留在本机。可以用 `--output` 更改压力报告路径。失败快照轮换保存在 `output/stability-failures/`，同样最多 10 组。

## 验证边界与后续

本轮两分钟检查足以复测连续查询和重复资料刷新，不能代表数小时游戏已验收。窗口移动检查验证了采集坐标，没有代替移动后的物理快捷键点击和浮卡位置验收。

仍需在真实动画中连续查询、调整分辨率后点击、更多 Windows 缩放及多显示器环境进行现场验证。当时资源占用约 2.5 GB，压力下个别查询超过 3 秒，后续优化结果见下节。中文参考译文仍需人工玩家审校；已有文字覆盖见[中文覆盖记录](chinese-coverage.md)。
